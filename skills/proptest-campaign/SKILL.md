# Property-testing campaigns: staging and role-scoped specialization

Every repository defines an implicit specification theory: which operations claim totality over arbitrary inputs versus partiality under **Design-by-Contract** caller preconditions, how repair depth scales with code ownership, and how confirmed findings route across pull requests, specification questions, or maintainer channels. Treat campaign setup as **Futamura staging and partial evaluation (`discover_repo >>= (\theory -> specialize(workflow, theory))`)**: recover that theory once at a pinned commit, residualize lean role-scoped sub-skills into an ephemeral external workspace, and hand each subagent only the skill and propositions its task requires.

Begin the coordinator session with this skill; load [`write-reports`](../write-reports/SKILL.md) (and [`root-and-branch`](../root-and-branch/SKILL.md) for owned repositories) when unfolding sub-skills, and pass [`proptest-praxis`](../proptest-praxis/SKILL.md) by explicit file path to module workers. Select and adapt the lenses below to match repository scale.

**Immutable baseline; ephemeral clone; provenance hygiene.** Pin the target commit (`target_sha`) up front and run inside an ephemeral external clone—such as `git clone --shared <repo> /tmp/<repo>-campaign/work` with state under `/tmp/<repo>-campaign/state/` and standalone artifacts under `/tmp/<repo>-campaign/out/`—so parallel worktrees, runner logs, regression seeds, and staged notes treat the developer's working checkout as an immutable input.

**Specification mining; evidentiary tiers; contributor conventions.** Delegate read-only reconnaissance at `target_sha` across documentation, contributor and governance guides (`README`, `CONTRIBUTING.md`, `.github/` templates, maintainer routing policies), public examples, manifests, CI/test runners, uncertainty markers (`TODO`, `FIXME`, `HACK`, `workaround`, `subtle`), **reactive single-input point-fixes** (hotfixes, release-blocker patches, urgent bounds-check commits—which frequently introduce adjacent regressions or update only one side of a coupled invariant), and **recently landed features meeting older consumers** (caches, visitors, serializers). Preserve each claim's exact source (`doc`, `example`, `test`, or `comment @ file:line`) so hints are never compressed into un-cited axioms.

**Value of information; precondition separation; speaker authority.** Present inferred defaults concisely and ask only the `2–4` unresolved questions with positive **value of information (`VoI`)**—questions whose answers branch API preconditions, repair depth (`surgical external diff` vs. owned-repo [`root-and-branch`](../root-and-branch/SKILL.md)), or deliverable routing (`branch PR`, `specification/tradeoff question`, `designated maintainer channel`). Separate documented caller preconditions from incidental habits of current callers, and record whether user-supplied expectations come from an API maintainer or a downstream caller (marking unattended assumptions as hypotheses).

**Partial evaluation; sub-skill unfolding; shared domain fixtures.** Residualize the repository's operating model once under `<campaign-dir>/state/`:
- `operating-model.md`: pinned `target_sha`, source-cited API contracts and caller preconditions (including verbatim user decisions tagged by API-owner vs. caller authority), non-goals, routing rules, and fast leaf-crate / `--release` / `Miri` / `ASan` / ephemeral-rootfs recipes.
- `domain-fixtures.md` (when several modules share one core IR, schema, or AST): shared miniature valid-AST builders, planted-instance recipes, and in-repo **McKeeman differential** pairs so workers reuse one canonical fixture vocabulary.
- `skills/<bucket>/SKILL.md`: one self-contained `20–30` line reporting guide per active deliverable bucket (specializing [`write-reports`](../write-reports/SKILL.md), plus [`root-and-branch`](../root-and-branch/SKILL.md) in owned mode) capturing admission criteria, baseline/fix verification commands, repair depth, and destination—written without cross-links to other skills so each writer runs as a closed, self-contained pass.
- `ledger.md`: covered modules and transitions, cleared guards (`file:line` proofs pruning repeated work), **Rely–Guarantee** `produce -> consume` obligations, and root-cause equivalence classes.

**Worktree autonomy; fast-loop separation; Rely–Guarantee composition.** Pass explicit absolute `SKILL.md` paths when delegating (subagent harnesses do not auto-expand `$skill` sigils). Give each module worker its own `git worktree`, [`proptest-praxis`](../proptest-praxis/SKILL.md), and a self-contained `10–15` line brief separating the `1–3s` fast check from conditional `--release`, `Miri`, `ASan`/`UBSan`, and ephemeral-rootfs filesystem runs, framing completion as a modular verification certificate (covered laws, minimal `#[test]`, candidate repair or characterization note, and any open interface assumptions). While a worktree and build cache are warm, workers also pursue adjacent in-module promises surfaced by code reading or testing. Treat open `produce -> consume` assumptions (`"produce omits X, assuming consume establishes X"`) and out-of-brief observations as leads: dispatch targeted checks verifying across supported inputs `x` that `produce(x)` satisfies `consume`'s precondition and promised input-output relation, recording whichever function establishes the condition.

**N-version decorrelation; fresh-eyes falsification; clean-branch replay.** Models from a single lineage share correlated blind spots. Route candidate findings through a fresh `read-only` reviewer—on a second model family when available—holding only the minimal test, decisive command and output, optional diff or options, module source at `target_sha`, and exact cited source (or verbatim user quote) for the promise. Read primary citations directly for competing interpretations, check witness minimality and `--release` / invariant coverage across sibling paths, name the tested API, and cite any inspected caller that alters the conclusion (`marking uninspected callers unverified`). Have the bucket writer verify pre-fix failure and post-fix pass under the decisive command and `--release` on a clean branch from `target_sha` (stacking dependent fixes explicitly when needed) or write standalone tradeoff/channel notes to `<campaign-dir>/out/<bucket>/`.

Use [`references/methods.md`](references/methods.md) when grounding these staging, modular-verification, and independent-review principles.
