# Property-testing campaigns: staging and role-scoped specialization

Every repository defines an implicit specification theory: which operations claim totality over arbitrary inputs versus partiality under **Design-by-Contract** caller preconditions, where newer modes cross older representation strata, how repair depth scales with code ownership, and how contributions sort across pull-request patches, specification discussions, or maintainer notes. Treat campaign orchestration as **Futamura staging (`discover_repo >>= (\theory -> specialize(workflow, theory))`) and experimental portfolio design**: map that theory once at a base commit, pair cross-module `produce -> consume` contracts that single-module tests never exercise together, compile lean role-scoped sub-skills into an external workspace, and conduct waves of focused subagents from an unclouded panoramic horizon.

Begin the coordinator session with this skill; load [`write-reports`](../write-reports/SKILL.md) (and [`root-and-branch`](../root-and-branch/SKILL.md) for owned repositories) when unfolding sub-skills, and pass [`proptest-praxis`](../proptest-praxis/SKILL.md) plus the single matched language/driver reference under `proptest-praxis/references/` (`rust.md`, `python.md`, `go.md`, or `rust-driver.md`) by explicit file path to module workers. Select and adapt the lenses below to match repository scale.

**Panoramic horizon; division of labor; declarative Nix and `run-ci` setup.** Record `target_sha` up front and work inside an ephemeral external workspace—such as `git clone --shared <repo> /tmp/<repo>-campaign/work` alongside `.git`-free module snapshots under `trees/`, plus `state/`, `env/`, `requests/`, `cases/`, `invariants/`, `reviews/`, and `out/`—so the developer's checkout remains an immutable input. Multi-wave campaigns thrive on **keeping the coordinator's horizon panoramic and uncompacted**: every raw source hunk, test script, patch diff, or long trace pulled into the coordinator permanently taxes subsequent waves and crowds out cross-module synthesis, user preferences, and coverage strategy. Focus the coordinator on **campaign cartography, cross-module hypothesis pairing, dependency dispatch, and `state/ledger.md` synthesis**: spawn every scout, worker, reviewer, and writer with a fresh, unforked context (`fork_turns: "none"` where supported so each subagent gets a clean context budget dedicated to its single puzzle), flow detailed artifacts outward as discrete `.md` files on disk (**pass-by-reference**), and steer via concise one-line status and ledger-row receipts. Route all toolchain checks, package or prebuilt-library provisioning, and build-environment setup through a dedicated **environment-setup subagent** scoped to `<campaign-dir>/env/` (using a fast lightweight model tier where the CLI supports per-subagent model selection): hand it a plain infrastructure ticket (`requests/env-<id>.md`), let it author declarative Nix files (`env/<id>.nix`, `nix-build --no-out-link`) or standalone manifests **plus a small `env/run-ci` wrapper script** (redirecting verbose compiler and CI debug output to log files and printing only compact `exit_code` and `file:line` frames) within `<campaign-dir>/env/` alone, and pass the resulting `env/<id>.md` receipt by path to workers.

**Specification mining; software archaeology; contributor conventions.** Split read-only discovery on `work/` at `target_sha` across two focused subagents so raw history prose never enters worker contexts:
- **Contract scout (`-> state/recon.md`):** survey documentation, contributor guides and project templates (`README`, `CONTRIBUTING.md`, `.github/` docs), public examples, manifests, CI build matrices, and uncertainty markers (`TODO`, `FIXME`, `HACK`, `workaround`, `subtle`), preserving exact source tags (`doc`, `example`, `test`, or `comment @ file:line`) and returning a short summary of open decision branches.
- **Repository archaeologist (`-> state/archaeology.md`):** run a dedicated `read-only` history pass on `work/` (`git log`, `git show`, `CHANGELOG`, zero compilation or test execution—optionally using a fast lightweight model tier to pre-digest noisy commit streams) tasked with reconstructing the codebase's **geological strata and invariant genealogy**: mapping original core assumptions (`Stratum 0`) versus retrofitted modes (`Stratum 1`: case-sensitivity, streaming, zero-copy, async), **evolutionary co-change couplings** (file/function pairs historically updated together where a recent change touched only one side), and **reactive guard clusters**, translating raw commit narratives into compact algebraic invariant deltas (`non-destructive input preservation`, `coupled sort/lookup invariant`, `unforwarded mode flag`) cited strictly by **current-`HEAD` `file:function` coordinates without historical commit SHAs**.

**Value of information; precondition separation; speaker authority.** Present inferred defaults concisely and pause to ask the `2–4` unresolved questions with positive **value of information (`VoI`)** whenever answers branch API preconditions, repair depth (`surgical external diff` vs. owned-repo [`root-and-branch`](../root-and-branch/SKILL.md)), contributor output buckets (`out/pr/`, `out/discussion/`, `out/maintainer/`), or host build constraints. Separate documented caller preconditions from incidental habits of current callers, and record whether user-supplied expectations come from an API maintainer or a downstream caller (marking unattended assumptions as hypotheses).

**Partial evaluation; sub-skill unfolding; shared domain fixtures.** Before dispatching module workers, write the repository's specialized operating model to `<campaign-dir>/state/`:
- `operating-model.md`: `target_sha`, source-cited API contracts and caller preconditions (including verbatim user decisions tagged by API-owner vs. caller authority), non-goals, contributor bucket rules, matched harness reference (`rust.md`, `python.md`, `go.md`, or `rust-driver.md`), and fast `0.5–3s` leaf-package / CI-matrix / `env/*.nix` recipes.
- `domain-fixtures.md` (when several modules share one core IR, schema, or AST): shared **uninterpreted finite sort** vocabularies (`Atom`, `Node`, `Scope`, `Seg`), miniature valid-AST builders, planted-instance recipes, and in-repo **McKeeman differential** pairs so workers reuse one canonical discrete-math fixture language.
- `skills/<bucket>/SKILL.md`: one self-contained `20–30` line authoring guide per active contributor bucket (specializing [`write-reports`](../write-reports/SKILL.md), plus [`root-and-branch`](../root-and-branch/SKILL.md) in owned mode) preserving counterexample-first clarity—inline concrete literal inputs, observed vs. expected values, a self-contained `10–25` line native regression test, pre-fix `Red` / post-fix `Green` CI commands, repair depth, and local `out/<bucket>/` destination—written as cohesive editorial guidance rather than a dry checklist, and without cross-links to other skills so each writer runs as a closed pass.
- `ledger.md`: index of module paths, `invariants/<module>.md` receipts (`Im(produce) subseteq Pre(consume) @ file:line`), `requests/<id>.md` tickets, and `cases/<id>.md` equivalence classes.

**Snapshot autonomy; outward case emission; Rely–Guarantee composition (`Im(f) subseteq Pre(g)`).** Pass explicit absolute file paths when delegating (subagent harnesses do not auto-expand `$skill` sigils). Materialize each module worker's directory as a clean, `.git`-free snapshot (`mkdir -p trees/<module> && git -C work archive <target_sha> | tar -x -C trees/<module>`—keeping `.git` strictly inside `work/` for the archaeologist and final clean-branch writers), and spawn an unforked worker (`fork_turns: "none"`) with [`proptest-praxis`](../proptest-praxis/SKILL.md), the single matched harness reference under `proptest-praxis/references/`, any `env/<id>.md` (`and env/run-ci`) receipt, and a self-contained `10–15` line brief separating the `0.5–3s` leaf loop from standard CI build-matrix checks (`--release`, `Miri`, `ASan`/`UBSan`, `-race`, ephemeral rootfs)—having the worker read its assigned skill and harness reference in full on its first turn so the specification repertoire guides `step_A` from the outset. Have each worker emit its outputs directly to disk—one atomic `cases/<module>-<n>.md` per failing case and candidate patch (`diff -ruN work/ trees/<module>/`), `invariants/<module>.md` for verified laws, and `requests/<id>.md` for open `Im(produce) \ Pre(consume)` obligations, `requests/arch-<id>.md` design-history questions (batched into the archaeologist before the next wave), or `requests/env-<id>.md` environment tickets—returning **only a one-line path and count receipt** to the coordinator. Dispatch targeted composition workers against `requests/<id>.md` (`testing consume(produce(x)) over x in Pre(produce)`), writing either a new `cases/<id>.md` or an updated `invariants/` proof.

**N-version decorrelation; per-case review; multi-wave continuation.** Route each `cases/<id>.md` path individually to a fresh, unforked `read-only` reviewer subagent (`fork_turns: "none"`, on a second model family when available) holding only that single `cases/<id>.md` path, `state/operating-model.md`, the module source at `target_sha`, and the cited contract source. Have the reviewer check primary citations for competing interpretations, test-case minimality, sibling call sites, CI release parity, caller status (`cited` vs. `unverified`), and **contributor bucket fit** under `operating-model.md`, write `reviews/<id>.md`, and return a single `state/ledger.md` row (`id | status | bucket | plain component-invariant summary`) so the coordinator updates `ledger.md` and dispatches a fresh unforked bucket writer (`holding only cases/<id>.md, reviews/<id>.md, and state/skills/<bucket>/SKILL.md`) to verify pre-fix `Red` and post-fix `Green` on a clean branch from `target_sha` or write the standalone note directly to `<campaign-dir>/out/<bucket>/<slug>.md`. Whenever the user asks for another pass or wave, plan the next wave strictly from `state/ledger.md`, `state/archaeology.md`, and `state/recon.md`—reading only `state/*.md` indices and one-line subagent receipts in the coordinator while delegating all source reads, property checks, and patches to fresh unforked (`fork_turns: "none"`) workers.

Use [`references/methods.md`](references/methods.md) when grounding these staging, modular-verification, and independent-review principles.
