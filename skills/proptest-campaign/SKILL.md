# Property-testing campaigns: staging and unfolding local skills

Every repository defines an implicit specification theory: which operations claim totality over arbitrary inputs versus partiality under **Design-by-Contract** caller preconditions, where newer modes cross older representation strata, how repair depth scales with code ownership, and how contributions sort across pull-request patches, specification discussions, or maintainer notes. Treat campaign orchestration as **staged partial evaluation**: map the repository's contract model once at a base commit, pair cross-module `produce -> consume` boundaries that single-module tests never exercise together, unfold context-specific skills into an external workspace, and coordinate focused subagent waves while keeping raw source code and test logs out of the coordinator's context.

Begin the coordinator session with this skill; load [`write-agent-prompts`](../write-agent-prompts/SKILL.md) and [`write-reports`](../write-reports/SKILL.md) (plus [`root-and-branch`](../root-and-branch/SKILL.md) for owned repositories) when unfolding per-bucket output skills under `state/skills/<bucket>/SKILL.md`, pass [`proptest-praxis`](../proptest-praxis/SKILL.md) plus the single matched language/driver reference under `proptest-praxis/references/` (`rust.md`, `python.md`, `go.md`, or `rust-driver.md`) by explicit file path to module workers, and pass [`mutation-challenger`](../mutation-challenger/SKILL.md) to green-suite challengers. Select and adapt the lenses below to match repository scale.

**Coordinator context budget; durable archive vs. selective outward projection.** Record `target_sha` up front and work inside an ephemeral external workspace—such as `git clone --shared <repo> /tmp/<repo>-campaign/work` alongside `.git`-free module snapshots under `trees/`, plus `state/`, `env/`, `requests/`, `cases/`, `invariants/`, `reviews/`, and `out/`—leaving the developer's checkout untouched. Treat `state/`, `reviews/`, and `env/logs/` as the durable verification archive so `out/` can remain a small, reader-focused engineering projection free of workspace plumbing. Keep raw source hunks, test scripts, patch diffs, and long traces out of the coordinator's context so multi-wave synthesis stays sharp: focus the coordinator on campaign cartography, cross-module hypothesis pairing, dependency dispatch, and `state/ledger.md` synthesis, keep independent challengers, per-case reviewers, and clean-branch writers fresh while letting each module worker own its snapshot across challenge and review feedback, close completed subagents at stage boundaries so active thread counts stay bounded, update `state/ledger.md`, `invariants/<module>.md`, `cases/<id>.md`, and `reviews/<id>.md` in place (recording tested snapshot or commit coordinates rather than creating parallel `*-index.md` or `*-progress.md` status files), and steer from concise one-line receipts.

**Host build runners; quiet CI wrappers; on-demand environment setup.** Reuse whatever build system, package manager, container runner, or test wrapper the repository and host environment already provide rather than prescribing a specific toolchain manager, deferring patch-only release gates (full benchmark suites, capability baselines, or heavy linters) until a confirmed production code change actually needs them. Keep verbose compiler and runner output in log files via a small `env/run-ci` wrapper script (wrapping the host's native build/test command so stdout prints only compact `exit_code` and `file:line` frames). Whenever a target genuinely lacks required compilers or test libraries on the host, delegate setup to a dedicated **environment-setup subagent** scoped strictly to `<campaign-dir>/env/` (using a fast lightweight model tier where the CLI supports per-subagent model selection) via `requests/env-<id>.md`—matching the host's native tooling and conventions—and pass the resulting `env/<id>.md` receipt by path to workers.

**Specification mining; software archaeology; contributor conventions.** Split read-only discovery on `work/` at `target_sha` across two focused subagents so raw history prose never enters worker contexts:
- **Contract scout (`-> state/recon.md`):** survey documentation, contributor guides and project templates (`README`, `CONTRIBUTING.md`, `.github/` docs), public examples, manifests, CI build matrices, and uncertainty markers (`TODO`, `FIXME`, `HACK`, `workaround`, `subtle`), preserving exact source tags (`doc`, `example`, `test`, or `comment @ file:line`) and returning a short summary of open decision branches.
- **Repository archaeologist (`-> state/archaeology.md`):** run a dedicated `read-only` history and architecture pass on `work/` (`CHANGELOG`, design docs, module history; zero compilation or test execution, optionally on a fast lightweight model tier) to map **architectural strata and mode interactions**. Contrast original core assumptions (`Stratum 0`) against retrofitted modes (`Stratum 1`: case-folding, streaming, zero-copy views, async cancellation, incremental caching), identify coupled subsystems (`serialize <-> parse`, `sort <-> lookup`, `planner <-> executor`), and pair **two-consumer shared-input paths** (`validate(raw) <-> execute(raw)`, `compute_len(x) <-> encode(x, buf)`, `fast_path(x) <-> general_path(x)`), summarizing invariant obligations (`non-destructive input preservation`, `coupled index maintenance`, `forwarded mode flags`) strictly by **current-`HEAD` `file:function` coordinates without commit SHAs**.

**Value of information; Wave-1 target selection; speaker authority.** Pair `state/recon.md` and `state/archaeology.md` hotspots with asking the user which subsystems worry them most to prioritize initial modules. Present inferred defaults concisely and pause to ask the `2–4` unresolved questions with positive **value of information (`VoI`)** whenever answers branch target selection, API preconditions, repair depth (`surgical external diff` vs. owned-repo [`root-and-branch`](../root-and-branch/SKILL.md)), contributor output buckets (`out/pr/`, `out/discussion/`, `out/maintainer/`), or host build conventions. Separate documented caller preconditions from incidental habits of current callers, and record whether user-supplied expectations come from an API maintainer or a downstream caller (marking unattended assumptions as hypotheses).

**Partial evaluation; unfolding repo-specific skills; shared domain fixtures.** Before dispatching module workers, write the repository's specialized operating model to `<campaign-dir>/state/`:
- `operating-model.md`: `target_sha`, source-cited API contracts and caller preconditions (including verbatim user decisions tagged by API-owner vs. caller authority), non-goals, contributor and AI-policy bucket rules, matched harness reference (`rust.md`, `python.md`, `go.md`, or `rust-driver.md`), and fast `0.5–3s` leaf-package / CI-matrix / host-runner recipes.
- `domain-fixtures.md` (when several modules will share executable builders over one core IR, schema, or AST): shared **uninterpreted finite sort** vocabularies (`Atom(0..3)`, `Node(0..3)`, `Scope(0..2)`, `Seg`), miniature valid-AST builders, planted-instance recipes, and in-repo **McKeeman differential** pairs so workers reuse one canonical discrete-math fixture language.
- `skills/<bucket>/SKILL.md`: unfold only the `1–2` distinct authoring skills the repository's workflow actually uses (`pr` or `patches` for external code fixes, `maintainer` for owned repos or human-reserved prose, adding a separate `discussion` or `repro-note` skill only when a reviewed case needs a non-patch tradeoff note—never cloning identical prose across placeholder buckets). Write `3–5` dense `**Concept; concept.**` paragraphs rather than line-counted checklists via [`write-agent-prompts`](../write-agent-prompts/SKILL.md) from [`write-reports`](../write-reports/SKILL.md)—plus [`root-and-branch`](../root-and-branch/SKILL.md) in owned mode—and **repo-wide** conventions in `state/recon.md` (keeping wave-specific module findings in `cases/` and `invariants/` so the bucket skill stays reusable across waves). Keep execution sandbox rules (`isolated worktree/branch`, `env/run-ci`, `no git push`) in the subagent's task brief rather than the writing skill so each skill carries pure editorial, git-shape, validation-scope, and domain judgment specific to that single bucket—*who reads this artifact, what decision it supports, what git/artifact shape the project uses, and which checks apply* (clean local commits on `fix/<slug>` with production test/lint/perf checks for code fixes, `git format-patch` series for mailing-list repos, `WIP` commits plus private technical notes when PR prose is human-reserved, or `repro/<slug>` / existing-test witnesses without production benchmark gates for specification questions).
- `ledger.md`: index of module paths, `invariants/<module>.md` receipts (`Im(produce) subseteq Pre(consume) @ file:line`), adequacy probe counts (`caught / uncaught`), `requests/<id>.md` tickets, and `cases/<id>.md` equivalence classes.

**Snapshot autonomy; Rely–Guarantee composition; upward caller lifting.** Pass explicit absolute file paths when delegating (subagent harnesses do not auto-expand `$skill` sigils). Materialize each module worker's directory as a clean, `.git`-free snapshot (`mkdir -p trees/<module> && git -C work archive <target_sha> | tar -x -C trees/<module>`—keeping `.git` strictly inside `work/` for the archaeologist and final clean-branch writers), and spawn a fresh worker subagent with [`proptest-praxis`](../proptest-praxis/SKILL.md), the single matched harness reference under `proptest-praxis/references/`, any `env/<id>.md` (`and env/run-ci`) receipt, and a self-contained `10–15` line brief separating the `0.5–3s` leaf loop from standard CI build-matrix checks (`--release`, `Miri`, `-O2 -DNDEBUG`, `-race`)—having the worker read its assigned skill and harness reference in full on its first turn so the specification repertoire guides `step_A` from the outset. Have each worker emit its outputs directly to disk—one atomic `cases/<module>-<n>.md` per failing case and candidate diff (`diff -ruN --exclude=.git work/ trees/<module>/` after removing temporary discovery-only dependencies), `invariants/<module>.md` for verified laws, and `requests/<id>.md` for open `Im(produce) \ Pre(consume)` obligations, `requests/lift-<id>.md` **upward caller-composition tickets**, `requests/arch-<id>.md` design-history questions, or `requests/env-<id>.md` environment tickets—returning **only a one-line path and count receipt** to the coordinator. Dispatch targeted composition workers against `requests/<id>.md` and `requests/lift-<id>.md`: test `consume(produce(x))` across `Pre(produce)`, and whenever a state-corrupting or framing discrepancy sits at an internal function `f`, trace callers upward (`public_entry -> ... -> f`) to test empirically whether valid top-level input reproduces `f`'s discrepancy under standard release builds (`--release` / `-O2 -DNDEBUG`).

**Mutation-adequacy stopping criterion.** Once a module worker completes its green `invariants/<module>.md` receipt, dispatch a separate fresh subagent with [`mutation-challenger`](../mutation-challenger/SKILL.md) (working in a disposable copy of `trees/<module>`) to test the new property suite directly across a concrete `6–10` probe plan of realistic semantic edits covering documented branches, boundary cutoffs, coupled state, and error-rollback paths that compile cleanly yet leave the property suite green while exhibiting a distinguishing input `x in Pre(f)`. Route surviving probes back to the module's `proptest-praxis` worker to widen the reference model or generator, then replay the declared probe set until `0` non-equivalent probes in that inventory survive, recording remaining untested dimensions plainly.

**Independent per-case review; oracle feedback; clean-branch output.** When all modules finish with zero confirmed defects or genuine contract ambiguities, leave `cases/` and `out/` empty without fabricating branches or reports. Otherwise route each `cases/<id>.md` path individually to a fresh `read-only` reviewer subagent (on a second model family when available) holding only that single `cases/<id>.md` path, `state/operating-model.md`, the module source at `target_sha`, and the cited contract source. Have the reviewer check primary citations and existing tests for competing interpretations, test-case minimality, sibling call sites, candidate-patch compatibility regressions, CI release parity, caller status (`cited` vs. `unverified`), and **contributor bucket fit** under `operating-model.md`, write `reviews/<id>.md`, and return a single `state/ledger.md` row (`id | status | bucket | plain component-invariant summary`). When a reviewer disproves a case because the worker's reference model assumed an unpromised guarantee (such as deterministic map iteration order), route that correction back to the module's `proptest-praxis` worker to repair its `step_A` oracle so invalid assumptions stop generating sibling false positives. In owned repositories, whenever `state/ledger.md` shows multiple confirmed cases sharing one representation gap or maintenance boundary, consolidate them into a single [`root-and-branch`](../root-and-branch/SKILL.md) pass rather than separate narrow patches; otherwise dispatch a fresh bucket writer (`holding only cases/<id>.md, reviews/<id>.md, and state/skills/<bucket>/SKILL.md`, working in an isolated `git worktree` of `work/` without pushing to any remote) to verify pre-fix `Red` and post-fix `Green` from `target_sha` (running heavy benchmark, capability, or lint gates only when production files change, and citing an existing in-tree test without a redundant commit when it already demonstrates a documentation question), commit any clean, convention-matched local branch (`fix/<slug>` or `repro/<slug>`) inside `<campaign-dir>/work/` (exporting `git format-patch` only when the project uses patch series), verify `git branch --show-current` matches the cited branch name, and stage one self-contained single-decision note `<campaign-dir>/out/<bucket>/<slug>.md` (noting the local branch and `git fetch <campaign-dir>/work fix/<slug>:fix/<slug>` handoff in the campaign summary)—keeping multi-module campaign summaries, adequacy inventories, and workspace status receipts strictly inside `state/ledger.md` rather than `out/`. Whenever the user asks for another pass or wave, plan the next wave strictly from `state/ledger.md`, `state/archaeology.md`, and `state/recon.md`—reading only `state/*.md` indices and one-line subagent receipts in the coordinator while delegating source edits, property checks, and commits to worker subagents.

Use [`references/methods.md`](references/methods.md) when grounding these staging, modular-verification, and independent-review principles.
