# Property-testing campaigns: staging and role-scoped specialization

Every repository defines an implicit specification theory: which operations claim totality over arbitrary inputs versus partiality under **Design-by-Contract** caller preconditions, where newer modes cross older representation strata, how repair depth scales with code ownership, and how confirmed findings route across pull requests, specification questions, or maintainer channels. Treat campaign orchestration as **Futamura staging (`discover_repo >>= (\theory -> specialize(workflow, theory))`) and experimental portfolio design**: map that theory once at a pinned commit, pair cross-module `produce -> consume` contracts that single-module tests never exercise together, compile lean role-scoped sub-skills into an external workspace, and conduct wave after wave of focused subagents from an unclouded panoramic horizon.

Begin the coordinator session with this skill; load [`write-reports`](../write-reports/SKILL.md) (and [`root-and-branch`](../root-and-branch/SKILL.md) for owned repositories) when unfolding sub-skills, and pass [`proptest-praxis`](../proptest-praxis/SKILL.md) plus the single matched language/driver reference under `proptest-praxis/references/` (`rust.md`, `python.md`, `go.md`, or `rust-driver.md`) by explicit file path to module workers. Select and adapt the lenses below to match repository scale.

**Panoramic horizon; division of labor; declarative Nix setup.** Pin `target_sha` up front and run inside an ephemeral external clone—such as `git clone --shared <repo> /tmp/<repo>-campaign/work` alongside `state/`, `env/`, `requests/`, `items/`, `invariants/`, `reviews/`, and `out/`—so the developer's checkout remains an immutable input. Multi-wave campaigns thrive on **keeping the coordinator's horizon panoramic and uncompacted**: every raw source hunk, test script, patch diff, or long trace pulled into the coordinator permanently taxes subsequent waves and crowds out cross-module synthesis, user preferences, and coverage strategy. Focus the coordinator on **campaign cartography, cross-module hypothesis pairing, dependency dispatch, and `state/ledger.md` synthesis**: spawn every scout, worker, reviewer, and writer with a fresh, unforked context (`fork_turns: "none"` where supported so each subagent gets a clean context budget dedicated to its single puzzle), flow detailed artifacts outward as discrete `.md` files on disk (**pass-by-reference**), and steer via concise one-line status and ledger-row receipts. Route all toolchain checks, package or prebuilt-library provisioning, and build-environment setup through a dedicated **environment-setup subagent** scoped to `<campaign-dir>/env/`: hand it a plain infrastructure ticket (`requests/env-<id>.md`), let it author declarative Nix files (`env/<id>.nix`, `nix-build --no-out-link`) or standalone environment manifests within `<campaign-dir>/env/` alone, and pass the resulting `.nix` / store-path receipt (`env/<id>.md`) by path to workers that need it.

**Specification mining; software archaeology; contributor conventions.** Split read-only discovery at `target_sha` across two focused subagents so raw history prose never bloats worker contexts:
- **Contract scout (`-> state/recon.md`):** survey documentation, contributor and governance guides (`README`, `CONTRIBUTING.md`, `.github/` templates, maintainer routing policies), public examples, manifests, CI/test runners, and uncertainty markers (`TODO`, `FIXME`, `HACK`, `workaround`, `subtle`), preserving exact source tags (`doc`, `example`, `test`, or `comment @ file:line`) and returning a short summary of open decision branches.
- **Repository archaeologist (`-> state/archaeology.md`):** run a dedicated `read-only` history pass (`git log`, `git show`, `CHANGELOG`, zero compilation or test execution) tasked with reconstructing the codebase's **geological strata and invariant genealogy**—mapping original core assumptions (`Stratum 0`) versus retrofitted modes (`Stratum 1`: case-sensitivity, streaming, zero-copy, async), **evolutionary co-change couplings** (file/function pairs historically updated together where a recent change touched only one side), and **reactive guard clusters**, translating raw commit narratives into compact algebraic invariant deltas (`disjoint-subtree ownership`, `coupled sort/lookup invariant`, `unforwarded mode flag`) while module workers stick to code-only hunks (`git show --format=""`).

**Value of information; precondition separation; speaker authority.** Present inferred defaults concisely and pause to ask the `2–4` unresolved questions with positive **value of information (`VoI`)** whenever answers branch API preconditions, repair depth (`surgical external diff` vs. owned-repo [`root-and-branch`](../root-and-branch/SKILL.md)), deliverable routing (`branch PR`, `specification/tradeoff question`, `designated maintainer channel`), or host build constraints. Separate documented caller preconditions from incidental habits of current callers, and record whether user-supplied expectations come from an API maintainer or a downstream caller (marking unattended assumptions as hypotheses).

**Partial evaluation; sub-skill unfolding; shared domain fixtures.** Before dispatching module workers, write the repository's specialized operating model to `<campaign-dir>/state/`:
- `operating-model.md`: pinned `target_sha`, source-cited API contracts and caller preconditions (including verbatim user decisions tagged by API-owner vs. caller authority), non-goals, routing rules, matched harness reference (`rust.md`, `python.md`, `go.md`, or `rust-driver.md`), and fast `0.5–3s` leaf-package / release / operational-check / `env/*.nix` recipes.
- `domain-fixtures.md` (when several modules share one core IR, schema, or AST): shared **uninterpreted finite sort** vocabularies (`Atom`, `Node`, `Scope`, `Seg`), miniature valid-AST builders, planted-instance recipes, and in-repo **McKeeman differential** pairs so workers reuse one canonical discrete-math fixture language.
- `skills/<bucket>/SKILL.md`: one self-contained `20–30` line reporting guide per active deliverable bucket (specializing [`write-reports`](../write-reports/SKILL.md), plus [`root-and-branch`](../root-and-branch/SKILL.md) in owned mode) preserving counterexample-first clarity—inline concrete literal inputs, observed vs. expected values, a self-contained `10–25` line native unit test, baseline/fix verification commands, repair depth, and destination—written as cohesive editorial guidance rather than a dry checklist, and without cross-links to other skills so each writer runs as a closed pass.
- `ledger.md`: index of module paths, `invariants/<module>.md` receipts (`Im(produce) subseteq Pre(consume) @ file:line`), `requests/<id>.md` tickets, and `items/<id>.md` equivalence classes.

**Worktree autonomy; outward item emission; Rely–Guarantee composition (`Im(f) subseteq Pre(g)`).** Pass explicit absolute file paths when delegating (subagent harnesses do not auto-expand `$skill` sigils). Give each unforked module worker (`fork_turns: "none"`) its own `git worktree`, [`proptest-praxis`](../proptest-praxis/SKILL.md), the single matched harness reference under `proptest-praxis/references/`, any needed `env/<id>.md` receipt, and a self-contained `10–15` line brief separating the `0.5–3s` leaf loop from conditional release, `Miri`, `ASan`/`UBSan`, `-race`, and ephemeral-rootfs runs—having the worker read its assigned skill and harness reference in full on its first turn so the specification repertoire guides `step_A` from the outset. Have each worker emit its outputs directly to disk—one atomic `items/<module>-<n>.md` per candidate divergence (recording test path, command, minimal input, cited contract, and candidate diff), `invariants/<module>.md` for verified laws, and `requests/<id>.md` for open `Im(produce) \ Pre(consume)` obligations or environment tickets—returning **only a one-line path and count receipt** to the coordinator. Dispatch targeted composition workers against `requests/<id>.md` (`testing consume(produce(x)) over x in Pre(produce)`), writing either a new `items/<id>.md` or an updated `invariants/` proof.

**N-version decorrelation; per-item bucket routing; clean-branch projection.** Route each `items/<id>.md` path individually to a fresh, unforked `read-only` reviewer subagent (`fork_turns: "none"`, on a second model family when available) holding only that single `items/<id>.md` path, `state/operating-model.md`, the module source at `target_sha`, and the cited contract source. Have the reviewer check primary citations for competing interpretations, witness minimality, sibling paths, release parity, caller status (`cited` vs. `unverified`), and **deliverable bucket fit** under `operating-model.md`'s routing rules, write `reviews/<id>.md`, and return a single `state/ledger.md` row (`id | verdict | bucket | plain component-invariant summary`) so the coordinator updates `ledger.md` and dispatches a fresh unforked bucket writer (`holding only items/<id>.md, reviews/<id>.md, and state/skills/<bucket>/SKILL.md`) to replay pre-fix failure and post-fix pass on a clean branch from `target_sha` or write the standalone note directly to `<campaign-dir>/out/<bucket>/<slug>.md`.

Use [`references/methods.md`](references/methods.md) when grounding these staging, modular-verification, and independent-review principles.
