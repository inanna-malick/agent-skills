# Agents and property tests: distilling and verifying the model

Every optimized subsystem—an indexed store, an evicting cache, an incremental query planner, a streaming parser, a zero-copy archive, a safe FFI wrapper—is a complex concrete machine `C` claiming to satisfy a much simpler specification `A`: either an exact abstraction function `alpha: C -> A` (`alpha(step_C(c, op)) == step_A(alpha(c), op)` against a `BTreeMap`, fresh recomputation, or tiny interpreter) or a soundness relation paired with a representation invariant `RepInv(c)` (such as an evicting cache returning `None` or the latest value while keeping tracked weight equal to live entries). Distill that specification into small executable code and let `proptest` explore thousands of state transitions on the CPU until the laws hold or shrink to a minimal counterexample.

When run standalone, resolve the user-requested target ref once at entry—defaulting to the current checkout `HEAD` (`target_sha = git rev-parse HEAD`)—and use that recorded `target_sha` everywhere afterward when managing worktrees and cutting clean fix branches; when invoked as a worker with a Module Conformance Brief (`$proptest-campaign`), stay inside the assigned worktree and return verified standalone unit tests, contract evidence, `target_sha`/`worker_base_sha` provenance (including any prerequisite repair dependencies), candidate diffs when the contract fixes an expected result (or concise option summaries when reproduction-only), and unverified boundary assumptions to the coordinator.

## 1. Objective, hermetic fixtures, and deliverables

Default to Rust `proptest`; use the repository's idiomatic equivalent (`hypothesis`, `fast-check`, `rapidcheck`, `RSpec` property helpers) in other languages. Offload state-space exploration to compiled code on the CPU rather than analyzing individual cases in tokens.

Maintain a local discovery branch containing naive reference models, `Arbitrary` generators, operation ASTs, and `RepInv` checks. This suite can grow to tens of thousands of lines and be repetitive or unoptimized (`O(n^2)` scans over a `Vec` are fine); its faithfulness to the contract matters, while production polish does not. Run parallel work in isolated `git worktree` checkouts on per-worker branches off the discovery branch, cap `CARGO_BUILD_JOBS` alongside pruning finished `target/` dirs (or sharing `CARGO_TARGET_DIR` per profile) so concurrent builds don't exhaust RAM or disk, and append log globs plus `proptest-regressions/` and `*.proptest-regressions` to `$(git rev-parse --git-path info/exclude)`. Assert inside properties with `prop_assert_eq!` / `prop_assert!` (which return `TestCaseError` silently during shrinking instead of printing hundreds of intermediate panic backtraces), format failure messages as equation diffs (`step {k} ({op:?}): alpha(impl) = {actual:?}, model = {expected:?}, rep_inv = {ok}`), and redirect verbose runner output to excluded log files, inspecting the tail on failure.

**Hermetic fixtures, OS write confinement, and `UNCHANGED` frame laws:** give every test touching paths, archives, package metadata, symlinks, config loaders, or cleanup routines a fresh per-case `TempDir` and an explicit frame condition (`modifies(work)`, `UNCHANGED(outside)`). Shrinking simplifies failing path strings toward `""`, `"."`, and `".."`—if code resolves relative to `cwd` or `$HOME`, or follows absolute paths, multi-level `".."` components, or outward symlinks, a child process started in `temp/work` can reach paths outside `temp` before post-hoc assertions run (especially in cleanup and extraction routines). Pass explicit `TempDir` paths or config structs wherever the API allows. Because `cargo nextest` isolates `#[test]` functions rather than individual `proptest` cases or shrink iterations—and dropping a failing case's `TempDir` after `set_current_dir` leaves subsequent shrink steps in an unlinked `cwd`—isolate code that reads `$HOME`, `$TMPDIR`, `$XDG_*`, or `cwd` from process globals by spawning a child `Command` (`.current_dir(&work_dir).env(...)`) per case. Whenever generators combine potentially escaping paths (leading `"/"`, `".."` segments, drive prefixes, or symlinks) with code that writes, unlinks, or extracts files, run the child process or test binary inside **OS-enforced write confinement** (such as Linux `bwrap --ro-bind / / --bind "$temp" "$temp"`, mount/user namespaces, or Landlock; macOS `sandbox-exec`; or a disposable container/VM with a read-only rootfs) so out-of-tree writes fail immediately with `EROFS`/`EACCES` at the kernel boundary while host files stay untouched. Inside that confined `temp/` root, place sentinel `temp/a` beside `temp/work/` and assert `snapshot_tree(temp, excluding = "work")` is `UNCHANGED` (catching single-level escapes to `temp/a` and unexpected sibling entries like `temp/b` using the generator's own `"a"`/`"b"` alphabet).

**Safe-wrapper soundness and build-profile parity:** in Rust and C/FFI wrappers, safe functions claim soundness across all inhabitants of their parameter types, including early `Err` returns and `Drop`. Where pure-Rust `unsafe` blocks, custom arenas, or `Pin` projections participate, run under `Miri` (`PROPTEST_DISABLE_FAILURE_PERSISTENCE=1 PROPTEST_CASES=16 cargo +nightly miri test` so `proptest` file persistence does not trip `Miri` isolation, or run `Miri` directly on deterministic `#[test]` cases); where C code or FFI bindings participate, compile with sanitizers (`ASan`, `UBSan`, `LSan`). Run instrumented checks at minimal sizes (such as `0–2` byte inputs, or decoupled safe-wrapper parameters like `bytes: b"a"` paired with `declared_count: 2`), use that check directly as the regression gate, and re-check divergences under `--release` (`-DNDEBUG`) alongside debug builds so `debug_assert!`-only checks are distinguished from release semantics.

For each confirmed divergence, produce a small deterministic `#[test]` unit assertion (named neutrally after the function and law, e.g., `remove_then_reinsert_preserves_bucket_weight`), exact `target_sha` / `worker_base_sha` provenance, contract evidence, and notes on any **unverified boundary assumptions** where the module assumes callers or downstream consumers enforce an undocumented invariant. When the contract establishes an expected result, supply a minimal candidate repair verified against the generalized property suite so it neither leaves sibling branches broken nor introduces regressions; when two defensible interpretations exist or changing behavior alters public semantics, layout, or complexity tradeoffs, keep the finding reproduction-only with a concise summary of the candidate interpretations.

## 2. Two-stage modeling and directing the search

**Contract-derived oracle, white-box generator (`Oracle from Contract ⊥ Generator from RepInv`):**
1. *Derive the reference model `A` from public docs, call sites, and domain invariants*—building it from clean standalone types (`BTreeMap`, `Vec`, small interpreters) independent of `C`'s internal helpers and fast-path branches—so the oracle expresses the intended contract directly.
2. *Inspect `C`'s concrete fields, constants, and shortcuts* to define `RepInv(c)` and aim generators directly at `C`'s internal boundaries: exact chunk/parallelism cutoffs (`16_384` bytes), truncated hash fingerprints (`(h >> 32) as u32`), deferred eviction queues that retain deleted keys, cached derived strings, and multi-phase registration order. When reading `C` surfaces a suspected discrepancy directly, formulate it in terms of `RepInv` or `alpha(step_C) != step_A(alpha)` and pin it down with an executable test so upstream guards and macros are exercised directly.

Keep compile-test-shrink loops in the `1–3s` range: start with self-contained leaf crates, and when an interesting module sits inside a heavyweight binary with a slow link step, build a narrow standalone test target, pocket crate, or single-object C/FFI test binary on the discovery branch so iteration stays instant.

Keep four lenses active throughout the investigation:

- **Observational equivalence across histories:** identical abstract contents `alpha(c1) == alpha(c2)` can conceal different caches, tombstones, allocation histories, sharing topologies, and lazy fields. Vary construction histories and observation points over deterministic `Vec<Op>` traces (using `loom`/`shuttle` separately when testing thread-scheduler races).
- **Generator support and algebraic collision density:** omitted interactions are unreachable; uniform 64-bit random draws rarely collide. Inspect and concentrate the generated distribution before increasing case counts.
- **Oracle and assertion fidelity:** keep model code self-contained and compare full `Result<T, E>` outcomes, element order, and multiplicity directly (sorting or deduplicating strictly where the contract specifies set/multiset semantics).
- **Unmasking deeper divergences and snapshot-restored calibration:** treat an all-green first run as a sensitivity question: snapshot the exact pre-mutation file bytes (or branch a disposable checkpoint worktree), inject a small deliberate invariant break, run the suite, and restore those exact saved bytes unconditionally **on both detection and non-detection**—confirming an empty diff against the pre-mutation snapshot so any in-progress candidate repair in the file stays intact. Because `proptest` stops at the shallowest divergence in a property, committing a validated candidate repair onto the worker/discovery branch (`advancing worker_base_sha`) and re-running the same suite routinely unmasks deeper divergences behind the first assertion; check sibling methods and parallel modules for the same representation gap.

**Mine existing tests, author uncertainty markers, and `Recent Feature × Older Consumer` pairs:**
- Existing strategies frequently constrain strings to narrow regexes (`"[a-z0-9_-]{1,12}"`), omitting quotes (`'`, `"`), even/odd backslash runs (`\\`, `\\"`), spaces, leading `-`, `\0`, and separators; existing `encode -> decode` tests often call lenient parsers that accumulate errors into a side field while returning `Ok(ast)`, or skip downstream evaluation (`to_args() -> clap::try_parse_from()`).
- Grep for author uncertainty markers (`TODO`, `FIXME`, `HACK`, `workaround`, `subtle`, `careful`)—they point straight to delicate representation invariants.
- Check `git log` for **recently added features, variants, or execution modes** and cross them against **older caches, visitors, serializers, hashers, and GC passes** whose implicit invariants predated the new variant, alongside sibling branches of recent bugfixes.

**Adaptive search allocation — exploration/exploitation:** get clean reference models running early and keep productive suites executing while building others. Allocate effort across new modules, stronger laws, sharper generators, and longer runs by expected information gain relative to compile/run cost. Retain runnable commands, tested revisions, behavioral coverage, and open boundary assumptions so work resumes cleanly.

## 3. Core algebraic laws and reference-model patterns

Before writing strategy code for a module, write down the explicit equations (`f(g(x)) == x`, `alpha(step_C) == step_A(alpha)`, `UNCHANGED(frame)`) and input partition classes the suite will check:

**Partial oracles and solution checking:** use properties that are cheaper to verify than to compute—validating path edges, topological order, preserved elements, and index invariants independently while distinguishing soundness (emitted items are valid) from completeness (all valid items are emitted).

- **Coupled representations, collections, caches, arenas, interning — commuting diagrams & `RepInv(c)`:** whenever a fast type maintains coupled views (map + eviction queue, primary + secondary index, overlay + backing store, LRU + pool), check for each modeled transition `op` that `alpha(step_impl(s, op)) == step_model(alpha(s), op)` (or the cache soundness relation) alongside `RepInv(step_impl(s, op))` across overwrites, removals, reinsertions, capacity boundaries, and empty/singleton states, recording which operations were covered.
- **Caches, incremental summaries, derived metadata — recomputation equivalence:** assert `cached_query(c) == recompute_from_scratch(alpha(c))` across warmups, size-preserving content edits, and transitive invalidations.
- **Graphs, traversals, query planners, AST rewrites — semantic preservation:** compare optimized traversals and rewritten plans against a tiny interpreter or small-instance exhaustive enumeration across cycles, diamonds, shared subgraphs, disconnected roots, and deletion holes.
- **Scoping, permissions, and visibility filters — predicate-table models:** compare fast routing, tenant-scoping, or field-visibility passes against an explicit `(actor, item, rule) -> bool` filter over a flat reference collection across generated schemas and requests.
- **Fallible transitions, partial-init `Drop`, and async `Future` cancellation (`StateT S (Except E)` vs. `ExceptT E (State S)`):** distinguish atomic rollback (`S -> Result<(A, S), E>`) from error-persisting state (`S -> (Result<A, E>, S)`) and un-reverted filesystem/cache effects. Schedule deterministic `Err` returns on step `k` (including partway through multi-step registration where teardown `Drop` runs on half-registered state), and step `Future`s manually with a custom waker over deterministic mock streams/channels yielding `Poll::Pending`—dropping them at arbitrary pending `.await` points—before continuing to use the shared structure.
- **Re-entrant trait hooks and callback interleaving:** whenever an operation updates internal state across calls to user-supplied trait methods or callbacks (`Ord::cmp`, `Hash`, `Iterator`, `Drop`, `serde` visitors, or custom resolvers), supply a test implementation whose callback queries or mutates the shared structure mid-operation and check `RepInv(c)` afterward.
- **Parsers, two-pass scanners, structured builders, and composed `produce -> consume` pipelines:** verify `parse(print(x)) == Ok(x)`, composed semantic and precondition preservation—for each supported input `x`, check that `produce(x)` satisfies the documented precondition of `consume` and check the promised relation between `x` and `consume(produce(x))` (such as `consume(produce(x)) == expected(x)` when the result is unique, or a solution-validity relation like valid topological ordering when multiple outputs are valid; avoiding stop-at-string assertions where `stringify -> reparse` crosses crate boundaries), and where a cited contract promises that a specific downstream observation `obs` ignores representation differences `x1 ~ x2`, check `obs(produce(x1)) == obs(produce(x2))` without requiring display/formatting paths to erase preserved spelling—plus streaming chunk homomorphism (`parse_chunks([a, b]) == parse_chunks([a ++ b])`). Where code scans input in two passes—a pre-splitter/boundary locator (`Pass 1`) followed by a slice parser (`Pass 2`), or right-to-left vs. left-to-right scanning—verify both passes agree on quote/escape parity (`\\"`) and token boundaries. Where a builder interpolates strings into data leaves (URLs, globs, filter expressions, queries, CLI args), check **AST spine invariance**: varying characters in data leaves must either return a clean validation `Err` or change only leaf values in the re-parsed AST, never outer AST constructors, operator counts, or scheme/authority fields.
- **Bounded decoders, streaming buffers, and resource trackers — monotonic budget invariants:** assert that configured byte, depth, and step bounds match actual output sizes and tracked counters across multi-chunk inputs and early `Err` returns.
- **Numeric/float cliffs and span/offset remapping:** check `0`, `1`, `cap ± 1`, exact fast-path thresholds (`T - 1`, `T`, `T + 1`), integer extrema, checked/wider reference arithmetic, and IEEE-754 float cliffs (`2^53` exact-integer boundary, `-0.0` vs. `+0.0` in `Eq`/`Hash`, `NaN` total-order violations, stateful Kahan compensation across retries). Across length-changing string maps (lossy UTF-8 replacement, normalization, escaping), verify that byte spans or indices are remapped into the new string rather than applied stale.
- **Quotient congruence (`x ~ y => obs(x) == obs(y)`), `Eq`/`Ord`/`Hash`, and zero-copy views:** whenever a type defines non-structural equivalence (`0!` epochs, trailing `.0`, `-` vs. `_`, insertion order, cached source text, `rkyv::Archived<T>` vs. owned `T`), verify `a == b => hash(a) == hash(b)`, `cmp(a, b) == Equal`, idempotence `norm(norm(x)) == norm(x)`, and agreement `obs(a) == obs(b)` on downstream observations whose contract promises representation-insensitivity (distinguishing lookup/evaluation semantics from original-spelling display).
- **Fast/parallel paths, copy-on-write, and validators:** compare batch vs. element-wise calls, parallel vs. serial execution right across chunk thresholds, branched snapshots before and after lazy-field initialization, and structural checkers on valid values vs. single-invariant perturbations.

## 4. Build high-density generators and shrinking-friendly ASTs

**Operation-sequence ASTs:** represent histories as an explicit `Op` enum (`Put`, `Get`, `Remove`, `Iter`, `Clear`, `Clone`, `FailAt(k)`, `CancelAtPoll(p)`) generated alongside tiny structural parameters (capacities `0..7`, chunk sizes `1..5`, threshold neighborhoods `T - 2..=T + 2`) read directly from `C`'s constants so boundary interactions fire constantly.

**Minimal algebraic alphabets over wordlists:** build string, path, URI, glob, and CLI generators combinatorially from tiny identifier atoms (`"a"`, `"b"`) crossed with the grammar's own punctuation (`'/'`, `':'`, `' '`, `'\\'`, `'"'`, `'*'`, `'-'`, `'.'`, `'\0'`, multibyte scalars) over lengths `0..8` rather than real paths or dictionaries. Small alphabets pack maximum delimiter-interaction density into minimal state space and shrink immediately to clean 2–5 character unit-test literals (`"/@a:a"`, `"\\[*]"`). Use `prop_recursive` for trees/ASTs and separate node/edge strategies to control DAG sharing and cycles.

**Deliberate equivalence-pair (`related_pair`) and decoupled strategies:** independent random draws `(x, y)` almost never satisfy `x ~ y`; generate `x` and apply equivalence-preserving rewrites (`0!` prefix, `.0` suffix, separator swaps, insertion permutations, `FromStr`/`Display` roundtrips) to produce `y`. Conversely, when safe parameters usually covary on happy paths (declared count vs. slice length, cached metadata vs. body), vary them independently across all safe Rust inhabitants.

**Small domains, handle mapping, and history motifs:** use `0..4` key pools and distinct replacement values so stale reads are immediately visible; map logical IDs to handles from reference state rather than trusting production outputs. Embed history motifs (`warm -> mutate -> read`, `remove -> reinsert`, `populate -> clear -> repopulate`, `snapshot -> mutate -> read_both`, `err_at_k -> continue`) inside arbitrary prefixes/suffixes, and vary operation weights across cases (swarm testing) so clears don't starve growth and reads don't mask uninitialized lazy state.

**Caller-habit independence, `sample::Index` shrinking, and RIPR calibration:** don't restrict generators to current outer-caller habits or discard a module contract failure merely because an outer caller currently passes fresh state—distinguish an explicit API precondition (including `unsafe` contracts, which tests must always uphold) from an incidental calling pattern. Prefer tuple `prop_map` and `proptest::sample::Index` (indexing into live reference-model state during execution) over heavy `prop_assume!` filters or deep `prop_flat_map` chains (which discard inner shrink state whenever an outer value shrinks). Include delayed-read traces so per-step assertions don't warm every cache, log behavioral-coverage counters to catch high no-op rates, and save standalone `#[test]` regressions alongside `proptest-regressions/` seeds.

## 5. Diagnose divergences and review with fresh eyes

Locate the first diverging step `k`, inspect both `step_C` and `step_A` to verify the reference model reflects the true contract, and isolate minimal triggering conditions by varying individual clauses of the shrunk witness. Encode generalized failure patterns back into the generator, sweep sibling methods and workspace occurrences of the same syntactic idiom (`rg` for repeated unchecked conversions, manual escaping, or stale cache mutations), and group counterexamples resolved by restoring one invariant into a single **root-cause equivalence class**.

**Fresh-eyes read-only check and base-commit replay:** before surfacing a finding or preparing a patch, replay the extracted `#[test]` directly on the pinned `target_sha` (the unrepaired baseline resolved at entry), and review it against the cited primary documentation, examples, speaker-tagged user decisions (`maintainer-confirmed` vs. `caller-expectation`), explicit preconditions, existing tests, and `--release` builds at `target_sha` in a fresh read-only context. When a second divergence found on a repaired discovery revision (`worker_base_sha`) is masked on `target_sha` by an earlier defect, replay it on `target_sha` plus the minimal prerequisite repair(s) and record `depends_on` explicitly so every packaged test fails pre-fix on its intended delivery base. Filter out oracle bugs, violations of documented caller preconditions, and unbounded resource inputs where no bound is promised; retain genuine module-contract divergences, naming the tested API and citing any inspected caller that changes the conclusion while marking uninspected callers `unverified` (distinguishing documented caller preconditions from incidental habits of current callers). Express every confirmed finding as a minimal deterministic `#[test]` over synthetic `"a"`/`"b"`/`TempDir` fixtures.

## 6. Extract fixes matched to repository ownership

When delegated a Module Conformance Brief by a campaign coordinator, return `(target_sha, worker_base_sha, depends_on, verified #[test] or observed diagnostic, delivery-base/--release/sanitizer output, contract evidence or open question, candidate diff or option summary, cross-module or follow-up leads)` to the coordinator.

When running standalone: use the `target_sha` resolved once at entry (`git rev-parse HEAD` of the selected target checkout) throughout. For **external open-source contributions**, cut a fresh branch from `target_sha` per root-cause equivalence class containing the deterministic `#[test]` regression and the smallest idiomatic repair—folding co-dependent repairs or stacking them in `depends_on` order when an earlier fix unmasks a deeper divergence—keeping reference models and broad generators on the local discovery branch. For **internal or team-owned codebases**, check whether recurring divergences or unwritten "don't pass that" bounds warrant tightening types so invalid or out-of-envelope states become unrepresentable (`|Type| == |ValidStates|`—such as parsing into a validated newtype once at the boundary, replacing boolean flag bags with sum types, or replacing internal `stringify -> reparse` hops with typed values) across sibling call sites.

When two defensible contract interpretations exist, or changing behavior affects public semantics, memory layout, or asymptotic complexity tradeoffs that maintainers should weigh directly, provide a reproduction-only unit test (pinning observed behavior alongside a contrastive baseline) and a concise option summary (using [`write-reports`](../write-reports/SKILL.md) if loaded); when `CONTRIBUTING.md`, `SECURITY.md`, or user instructions designate a non-public maintainer path for a finding, stage the minimal unit test and notes on that path.

Whenever the contract establishes an expected result, verify on the intended delivery base (`target_sha`, or `target_sha` plus declared `depends_on` repairs) that the unit test fails for the expected reason before the fix and passes after it, rerun the assigned law over the recorded operations (e.g., `alpha(step_impl(s, op)) == step_model(alpha(s), op)` for an exact state-machine model, or the cache/solution soundness relation, alongside `RepInv(s)`, `--release`, and relevant sanitizer/`Miri` checks) on the discovery branch without introducing regressions, commit validated fixes onto the local discovery branch (`recording the updated worker_base_sha`) to unmask deeper layers, and continue exploring.
