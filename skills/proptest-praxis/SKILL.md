# Agents and property tests: distilling and verifying the model

Every optimized subsystem—an indexed store, an evicting cache, an incremental query planner, a streaming parser, a zero-copy archive, a safe FFI wrapper—is a concrete state machine `C` claiming a Hoare/Lamport **refinement mapping** `alpha: C -> A` (`alpha(step_C(c, op)) == step_A(alpha(c), op)` against a `BTreeMap`, fresh recomputation, or small-step interpreter) or a **forward simulation** relation paired with a representation invariant `RepInv(c)` (such as an evicting cache returning `None` or the latest value while keeping tracked weight equal to live entries). Distill that specification into small executable code and let `proptest` explore thousands of state transitions on the CPU until the diagram commutes or shrinks to a minimal counterexample.

When run standalone, resolve the user-requested target ref once at entry—defaulting to the current checkout `HEAD` (`target_sha = git rev-parse HEAD`)—and use that recorded `target_sha` everywhere afterward when managing worktrees and cutting clean fix branches; when invoked as a worker with a Module Conformance Brief (`$proptest-campaign`), work inside the assigned worktree and return the structured outcome packet to the coordinator.

## 1. Two-stage modeling and directing the search

**Contract-derived oracle, white-box generator (`Oracle from Contract ⊥ Generator from RepInv`):**
1. *Derive the reference model `A` from public docs, call sites, and domain invariants*—building it from clean standalone types (`BTreeMap`, `Vec`, small interpreters) independent of `C`'s internal helpers and fast-path branches—so the oracle expresses the intended contract directly.
2. *Inspect `C`'s concrete fields, constants, and shortcuts*—noting every field on `C` that disappears under `alpha(c)`—to define `RepInv(c)` and aim generators directly at `C`'s internal boundaries: exact chunk/parallelism cutoffs (`16_384` bytes), truncated hash fingerprints (`(h >> 32) as u32`), deferred eviction queues that retain deleted keys, cached derived strings, and multi-phase registration order. When reading `C` surfaces a suspected discrepancy directly, express it as `RepInv` or `alpha(step_C) != step_A(alpha)` and pin it down with an executable test so upstream guards and macros are exercised directly.

Keep compile-test-shrink loops in the `1–3s` range: start with self-contained leaf crates, and when an interesting module sits inside a heavyweight binary with a slow link step, build a narrow standalone test target, pocket crate, or single-object C/FFI test binary on the discovery branch so iteration stays instant.

Keep four lenses active throughout the investigation:

- **Myhill–Nerode state distinguishability across histories:** two histories `h1, h2` reaching the same abstract state `alpha(c1) == alpha(c2)` often leave distinct hidden residues in `C`—warmed caches, tombstones, freelist layouts, sharing topologies, unforced lazy fields—waiting for one distinguishing suffix `w` to separate them. Vary construction histories and observation points over deterministic `Vec<Op>` traces (using `loom`/`shuttle` separately when testing thread-scheduler linearizability).
- **Small-scope collision density (Jackson's small-scope hypothesis):** omitted interactions never fire, and uniform 64-bit draws almost never collide. Pack maximum birthday-paradox collision density into tiny domains before increasing case counts.
- **Oracle and assertion fidelity:** keep model code self-contained: check `Ok`/`Err` variant agreement, compare inner values through the fields and observations the contract promises, preserve both order and counts for sequences, sort while preserving counts for multisets, and deduplicate strictly for sets.
- **Mutation adequacy and unmasking deeper layers:** treat an all-green first run as a mutation-adequacy experiment: snapshot the exact pre-mutation file bytes (or branch a disposable checkpoint worktree), introduce a small deliberate invariant break, run the suite to watch the property catch it, and restore those exact saved bytes unconditionally **on both detection and non-detection**—confirming an empty diff against the snapshot so any in-progress candidate repair stays intact. Catching a calibration mutant turns a clean run into concrete verification evidence. When a real failure surfaces, `proptest` stops at the shallowest divergence: committing a validated repair onto the worker/discovery branch (`advancing worker_base_sha`) and re-running the suite routinely unmasks deeper layers behind the first assertion; check sibling methods and parallel modules while the model is hot.

**Mine existing tests, uncertainty markers, fix neighborhoods, and `Recent Feature × Older Consumer` pairs:**
- Existing strategies frequently constrain strings to narrow regexes (`"[a-z0-9_-]{1,12}"`), omitting quotes (`'`, `"`), even/odd backslash runs (`\\`, `\\"`), spaces, leading `-`, `\0`, and separators; existing `encode -> decode` tests often call lenient parsers that accumulate errors into a side field while returning `Ok(ast)`, or skip downstream evaluation (`to_args() -> clap::try_parse_from()`).
- Grep for author uncertainty markers (`TODO`, `FIXME`, `HACK`, `workaround`, `subtle`, `careful`)—they point straight to delicate representation invariants.
- Audit the neighborhood of **recent reactive point-fixes** (*"How Do Fixes Become Bugs?"*—hotfixes, release-blocker patches, security fixes, crash band-aids): hurried patches written against one reported input frequently carry adjacent correctness impacts—updating one half of a coupled invariant (e.g., changing growth from `*= 2` to `+ 128` while an adjacent reset still assumes `*= 2`), regressing `--release` or error-cleanup paths, or guarding a single call site while sibling methods share the same assumption. Reconstruct the general `RepInv(c)` or commuting law the commit aimed to restore and verify the surrounding module and sibling paths against it, alongside **recently added features/modes** crossed against **older caches, visitors, serializers, hashers, and GC passes**.

**Adaptive search allocation — breadth vs. depth:** get clean reference models running early and keep productive suites executing while building others. Allocate effort across new modules, stronger laws, sharper generators, and longer runs by expected information gain relative to compile/run cost. Retain runnable commands, tested revisions, covered operations, and open cross-module assumptions so work resumes cleanly.

## 2. Core algebraic laws and reference-model patterns

Before writing strategy code for a module, pick the strongest applicable rung on **Hughes's specification ladder** (`Refinement Mapping -> In-Repo McKeeman Differential Pair -> Commuting Paths ("two ways to reach the same state") -> EMI / Metamorphic Rewrite -> Planted-Solution / Blum Checker -> RepInv Conservation`) so every suite checks a real equation rather than `is_ok()` smoke assertions:

**In-repo differential pairs, Blum result checkers, and `EMI` / metamorphic relations:** check whether the repository *already* contains a second path for the same contract (**McKeeman differential testing**: `SIMD vs. scalar fallback`, `incremental vs. cold batch`, `streaming vs. whole-slice`, `JIT vs. interpreter`, `Borrowed/Archived vs. Owned`). When outputs are non-unique or expensive to compute from scratch, verify certificates in linear time (**Blum result checkers**: validating path edges, topological order + multiset preservation, or primal-dual optimality while distinguishing soundness from completeness), or apply **metamorphic / equivalence-modulo-inputs (`EMI`)** rewrites (`e ~ e' => eval(e) == eval(e')`: reordering independent clauses, pruning dead branches, splitting chunks, or scaling weights so `f(transform(x)) == g(f(x))` without a separate reference solver).

- **Coupled representations, collections, caches, arenas, interning — refinement mappings & `RepInv(c)`:** whenever a fast type maintains coupled views (map + eviction queue, primary + secondary index, overlay + backing store, LRU + pool), check for each modeled transition `op` that `alpha(step_impl(s, op)) == step_model(alpha(s), op)` (or the cache forward-simulation relation) alongside `RepInv(step_impl(s, op))` across overwrites, removals, reinsertions, capacity boundaries, and empty/singleton states, recording which operations were covered.
- **Caches, incremental summaries, derived metadata — recomputation naturality:** assert `cached_query(c) == recompute_from_scratch(alpha(c))` across warmups, size-preserving content edits, mode switches, and transitive invalidations.
- **Graphs, traversals, query planners, AST rewrites — bisimulation & big-step equivalence:** compare optimized traversals and rewritten plans against a small-step interpreter or small-instance exhaustive enumeration across cycles, diamonds, shared DAG subgraphs, disconnected roots, and deletion holes.
- **Scoping, permissions, and visibility filters — relational-calculus models:** compare fast routing, tenant-scoping, or field-visibility passes against an explicit `(actor, item, rule) -> bool` comprehension over a flat reference collection across generated schemas and requests.
- **Fallible transitions, external `IO`/cache effects, partial-init `Drop`, and `Future` cancellation (`StateT S (Except E)` vs. `ExceptT E (State S)`):** distinguish atomic rollback (`S -> Result<(A, S), E>`) from error-persisting state (`S -> (Result<A, E>, S)`) and **external filesystem, cache-directory, or symbol-table mutations that survive `Err` and RAII brackets** (such as staging a file into a shared cache before validation fails, or removing an in-memory index entry when disk removal returns `Err`). Schedule deterministic `Err` returns on step `k` (including partway through multi-step registration where `Drop` runs on half-registered state), and step `Future`s manually with a custom waker over deterministic mock streams/channels yielding `Poll::Pending`—dropping them at arbitrary pending `.await` suspension points—before continuing to use the shared structure.
- **Layered configs, option merges, and non-commutative precedence monoids:** check associativity, identity (`None` vs. `Some(empty)`), and `first-wins` vs. `last-wins` precedence across CLI flags, environment variables, defaults, and multi-step session or request merges (including options retained from a rejected or retried step).
- **Re-entrant trait hooks and callback interleaving:** whenever an operation temporarily opens `RepInv(c)` across calls to user-supplied trait methods or callbacks (`Ord::cmp`, `Hash`, `Iterator`, `Drop`, `serde` visitors, or custom resolvers), supply a test implementation whose callback queries or mutates the shared structure mid-operation and check `RepInv(c)` afterward.
- **Section–retraction pairs, two-pass scanners, and Rely–Guarantee `produce -> consume` pipelines:** verify `parse(print(x)) == Ok(x)`, composed semantic and precondition preservation—for each supported input `x`, check that `produce(x)` satisfies the documented `Rely` precondition of `consume` and fulfills the promised relation between `x` and `consume(produce(x))` (such as `consume(produce(x)) == expected(x)` when unique, or a Blum result-checker relation like valid topological ordering when multiple outputs are valid; pushing assertions across `stringify -> reparse` module boundaries), and where a cited contract promises that a specific downstream observation `obs` ignores representation differences `x1 ~ x2`, check `obs(produce(x1)) == obs(produce(x2))` while letting display/formatting paths preserve original spelling—plus monoidal chunk homomorphism (`parse_chunks([a, b]) == parse_chunks([a ++ b])`). Where code scans input in two passes—a pre-splitter/boundary locator (`Pass 1`) followed by a slice parser (`Pass 2`), or right-to-left vs. left-to-right scanning—verify both passes induce identical quote/escape parity (`\\"`) and token boundaries. Where a builder interpolates strings into data leaves (URLs, globs, filter expressions, queries, CLI args), check **AST spine invariance**: varying characters in data leaves must either return a clean validation `Err` or change leaf values alone in the re-parsed AST, keeping outer AST constructors, operator counts, and scheme/authority fields invariant.
- **Bounded decoders, streaming buffers, and resource trackers — conservation & budget invariants:** assert that configured byte, depth, and step bounds match actual output sizes and tracked counters across multi-chunk inputs and early `Err` returns.
- **Numeric/float cliffs and Galois span pushforwards:** check `0`, `1`, `cap ± 1`, exact fast-path thresholds (`T - 1`, `T`, `T + 1`), integer extrema, checked/wider reference arithmetic, and IEEE-754 non-associativity cliffs (`2^53` exact-integer boundary, `-0.0` vs. `+0.0` in `Eq`/`Hash`, `NaN` total-order breaks, stateful Kahan compensation across retries). Across length-changing string maps (lossy UTF-8 replacement, Unicode normalization, escaping), verify byte spans push forward along the edit map rather than indexing stale coordinates.
- **Quotient algebras (`x ~ y => obs(x) == obs(y)`), `Eq`/`Ord`/`Hash` congruence, and zero-copy views:** whenever a type carries non-canonical representations (`0!` epochs, trailing `.0`, `-` vs. `_`, insertion order, cached source text, `rkyv::Archived<T>` vs. owned `T`), verify kernel congruence `a == b => hash(a) == hash(b)`, `cmp(a, b) == Equal`, idempotent canonicalization `norm(norm(x)) == norm(x)`, and agreement `obs(a) == obs(b)` on downstream observations whose contract promises representation-insensitivity (distinguishing lookup/evaluation semantics from original-spelling display).
- **Fast/parallel paths, `plan` vs. `apply` (`M_scan == M_apply`), projection symmetry, and CoW:** compare batch vs. element-wise calls, parallel vs. serial execution right across chunk thresholds, dry-run / pre-scan / `list_entries` / size-calculation passes against actual execution / `extract_entries` passes, validators that inspect one projection (leaf strings, primary headers, first duplicate key) while serializers or evaluators read another (map keys, metadata, trailing duplicate keys, empty-body defaults `"" -> "{}"`), and branched snapshots before and after lazy-field initialization.

## 3. Build high-density generators and shrinking-friendly ASTs

**Operation-sequence ASTs:** represent histories as an explicit `Op` enum (`Put`, `Get`, `Remove`, `Iter`, `Clear`, `Clone`, `FailAt(k)`, `CancelAtPoll(p)`) generated alongside tiny structural parameters (capacities `0..7`, chunk sizes `1..5`, threshold neighborhoods `T - 2..=T + 2`) read directly from `C`'s constants so boundary interactions fire constantly.

**Minimal algebraic alphabets over wordlists:** build string, path, URI, glob, and CLI generators combinatorially from tiny identifier atoms (`"a"`, `"b"`) crossed with the grammar's own punctuation (`'/'`, `':'`, `' '`, `'\\'`, `'"'`, `'*'`, `'-'`, `'.'`, `'\0'`, multibyte scalars) over lengths `0..8`. Small alphabets pack maximum delimiter-interaction density into minimal state space and shrink immediately to clean 2–5 character unit-test literals (`"/@a:a"`, `"\\[*]"`). Use `prop_recursive` for trees/ASTs and separate node/edge strategies to control DAG sharing and cycles.

**Planted-solution (`inverse`), equivalence-pair (`related_pair`), and decoupled strategies:** for hard constraint, dependency-resolution, or planning domains, generate a valid witness/solution *first* and construct the problem instance around it (planted resolution graph, known-answer AST plus distractor clauses). Planting proves **feasibility**: check that the solver accepts the instance and returns an output satisfying the Blum result checker. When the API promises **exact optimality** (or an explicit approximation guarantee that implies the comparison), also check that the returned objective meets that guarantee relative to the planted candidate (`cost <= cost(planted)` for exact minimization, `score >= score(planted)` for exact maximization—bounding the result without claiming global optimality; for best-effort heuristics without an optimality guarantee, check feasibility and record large objective gaps as observations, and compare against the exact planted witness only when uniqueness holds). Because independent random draws `(x, y)` rarely satisfy `x ~ y`, generate `x` and apply equivalence-preserving rewrites (`0!` prefix, `.0` suffix, separator swaps, insertion permutations, `FromStr`/`Display` roundtrips) to produce `y`. Conversely, when safe parameters usually covary on happy paths (declared count vs. slice length, cached metadata vs. body), vary them independently across all safe Rust inhabitants.

**Small domains, mixed Groce swarm subsets, and history motifs:** use `0..4` key pools and distinct replacement values so stale reads stand out immediately; map logical IDs to handles from reference state. Embed history motifs (`warm -> mutate -> read`, `remove -> reinsert`, `populate -> clear -> repopulate`, `snapshot -> mutate -> read_both`, `err_at_k -> continue`) inside arbitrary prefixes/suffixes, and **mix Groce swarm-subset traces** (drawing `3–5` `Op` variants and feature-flag combinations per trace so `Clear` and eager `Get` do not suppress `Resize` or cold `Snapshot`s) **with full-vocabulary traces (`AllOps`)** so interactions requiring six or more distinct operations remain reachable.

**Caller-habit independence, `sample::Index` / label-keyed shrinking, and RIPR observability:** test the full domain permitted by explicit API preconditions (upholding documented `unsafe` contracts while varying everything callers merely happen to keep constant today). Prefer tuple `prop_map` and `proptest::sample::Index` (indexing into live reference-model state during execution) over heavy `prop_assume!` filters or deep `prop_flat_map` chains (which reset inner shrink state when an outer value shrinks); when building custom procedural generators outside `proptest` combinators, key PRNG draws by `(label, occurrence)` and shrink container counts before leaf values so shrinking a loop bound leaves downstream leaf choices invariant. Check that generated fixtures make competing modes or branches produce observably distinct answers, log behavioral-coverage counters to spot no-op branches, and keep standalone `#[test]` regressions alongside `proptest-regressions/` seeds.

## 4. Run hermetically on CPU and sanitizers

Default to Rust `proptest`; use the repository's idiomatic equivalent (`hypothesis`, `fast-check`, `rapidcheck`, `RSpec` property helpers) in other languages, running exploration in compiled CPU code. Maintain a local discovery branch where naive models (`O(n^2)` scans over a `Vec` are fine), `Arbitrary` generators, and `RepInv` checks can grow freely. Run parallel investigations in isolated `git worktree` checkouts on per-worker branches off the discovery branch, and cap `CARGO_BUILD_JOBS` alongside pruning finished `target/` dirs (or sharing `CARGO_TARGET_DIR` per profile). When running standalone (in `$proptest-campaign`, the coordinator manages shared Git excludes once for all worktrees), record pre-existing untracked/ignored paths (`git status --porcelain --ignored`) before setup and honor the repository's seed policy: check `git ls-files '*proptest-regressions*' '**/proptest-regressions/**'` and `.gitignore` first, add log paths (plus `proptest-regressions/` and `*.proptest-regressions` only when the repo tracks no seeds anywhere in the workspace) inside a marked `# begin/end proptest-praxis` block in `$(git rev-parse --git-path info/exclude)`, and at cleanup remove **only** logs/seeds created by this run **before** removing that block—confirming `git add -n .` lists zero newly created temporary artifacts while leaving pre-existing developer files untouched. Assert inside properties with `prop_assert_eq!` / `prop_assert!` (returning `TestCaseError` cleanly during shrinking), format failure messages as equation diffs (`step {k} ({op:?}): alpha(impl) = {actual:?}, model = {expected:?}, rep_inv = {ok}`), and redirect runner output to excluded log files, inspecting the tail when a property fires.

**Hermetic fixtures, OS write confinement, and Reynolds frame laws (`modifies(work) * UNCHANGED(outside)`):** give every test touching paths, archives, package metadata, symlinks, config loaders, or cleanup routines a fresh per-case `TempDir` and an explicit separating frame (`modifies(work)`, `UNCHANGED(outside)`), keeping pure in-memory path parsing in-process and cheap. Shrinking simplifies failing path strings toward `""`, `"."`, and `".."`—if mutating code resolves relative to `cwd` or `$HOME`, or follows absolute paths, multi-level `".."` components, or outward symlinks, a child process started in `temp/work` can reach paths outside `temp` before post-hoc assertions run (especially in cleanup and extraction routines). Pass explicit `TempDir` paths or config structs wherever the API allows, and isolate process-global `$HOME`, `$TMPDIR`, `$XDG_*`, or `cwd` reads by spawning a child `Command` (`.current_dir(&work_dir).env(...)`) per case (since `cargo nextest` isolates `#[test]` functions rather than individual shrink iterations). Whenever generated paths reach operations that write, unlink, or extract files:
1. Run the child process or test binary inside **OS-enforced write confinement** (Linux `bwrap --ro-bind / / --bind "$temp" "$temp"`, mount/user namespaces, or Landlock; macOS `sandbox-exec`; or a disposable container/VM) so host files stay protected.
2. Because an implementation that swallows `EROFS`/`EACCES` (`let _ = fs::remove_file(...)`) would leave a read-only outer mount silent and `temp/` unchanged, place *every* target root inside the snapshotted `temp/` tree: nest `temp/d1/d2/work/` deeper than generated `".."` depth with writable ancestor sentinels `temp/a`, `temp/d1/a`, `temp/d1/d2/a` (and when testing leading `"/"` or symlinks, mount/pivot `temp/root_fs/` with its own writable sentinel `temp/root_fs/a` inside that same snapshot), preflighting each active path class once with a deliberate out-of-`work` write to confirm `snapshot_tree(temp, excluding = "d1/d2/work") == UNCHANGED` observes it (marking denied/unobservable operations `inconclusive` for the implementation law).

**Safe-wrapper soundness and build-profile parity:** in Rust and C/FFI wrappers, safe functions claim soundness across all inhabitants of their parameter types, including early `Err` returns and `Drop`. Where pure-Rust `unsafe` blocks, custom arenas, or `Pin` projections participate, run under `Miri` (`PROPTEST_DISABLE_FAILURE_PERSISTENCE=1 PROPTEST_CASES=16 cargo +nightly miri test` so `proptest` file persistence coexists cleanly with `Miri` isolation, or run `Miri` directly on deterministic `#[test]` cases); where C code or FFI bindings participate, compile with sanitizers (`ASan`, `UBSan`, `LSan`). Run instrumented checks at minimal sizes (such as `0–2` byte inputs, or decoupled safe-wrapper parameters like `bytes: b"a"` paired with `declared_count: 2`), use that check directly as the regression gate, and re-check divergences under `--release` (`-DNDEBUG`) alongside debug builds so `debug_assert!`-only checks are distinguished from release semantics.

## 5. Diagnose, replay on `target_sha`, and extract fixes

When a run surfaces a failing seed or sanitizer backtrace, read it directly as a state-transition equation: locate the first diverging step `k`, inspect `step_C` alongside `step_A` and `RepInv(c)` to verify which documented promise (or open Rely–Guarantee obligation) governs that state, and apply **delta-debugging (`ddmin`)** across individual clauses of the shrunk witness to isolate minimal conditions. Fold generalized failure patterns back into the generator, sweep sibling methods and workspace occurrences of the same syntactic idiom (`rg` for repeated unchecked conversions, manual escaping, or stale cache mutations), and quotient counterexamples resolved by restoring one invariant into a single **root-cause equivalence class** with a neutral test name (`remove_then_reinsert_preserves_bucket_weight`).

**Greenfield boundary test, fresh-eyes check, and base-commit replay:** write the final standalone `#[test]` fresh from scratch **at the exact API boundary whose contract was established**—public crate API for external promises, or the native module test boundary for internal invariants—over synthetic `"a"`/`"b"`/`TempDir` fixtures without discovery-branch models or generator imports. Branch by contract clarity before surfacing a result:
- **Settled contract violation:** apply the test-only diff onto a disposable checkout of `target_sha` (or `target_sha` plus minimal `depends_on` repairs when masked by an earlier defect) and confirm the named `#[test]` **ran and failed with the expected diagnostic** across debug/`--release` (and `gate_command` when sanitizer-gated).
- **Unsettled specification (`open_question`):** when docs are silent between two defensible behaviors (such as `first-wins` vs. `last-wins` on duplicate keys), write a deterministic `#[test]` that **demonstrates the current observed behavior** on `target_sha` alongside the competing interpretations and the gap in the documentation—a passing characterization test is sufficient without asserting an unpromised expectation just to turn the test red.
Review every candidate in a fresh read-only context against the cited primary documentation, examples, speaker-tagged verbatim decisions (`api-owner-confirmed` vs. `caller-expectation`), explicit preconditions, and existing tests at `target_sha`. Filter out oracle bugs, violations of documented caller preconditions, and unbounded resource inputs where no bound is promised; retain genuine module-contract divergences and well-grounded open questions, naming the tested API and citing any inspected caller that changes the conclusion while marking uninspected callers `unverified` (distinguishing documented caller preconditions from incidental habits of current callers).

When delegated a Module Conformance Brief by a campaign coordinator, return the structured `Worker Outcome` packet (`status` including `inconclusive` when calibration or transition reach is incomplete, `target_sha`, `worker_base_sha`, `depends_on`, `law_checked` and `promise_source`, `domain`, `ops_covered`, `case_count`, and `calibration_break_caught`, `witness` with minimal `#[test]`, exact `gate_command` + feature/sanitizer/`Miri` flags, `expected_diagnostic`, and delivery-base/`--release` output, candidate diff or option summary, and cross-module or follow-up leads).

When running standalone, use the `target_sha` resolved once at entry (`git rev-parse HEAD` of the selected target checkout) throughout:
- **External open-source contributions:** cut a fresh branch from `target_sha` per root-cause equivalence class containing the deterministic `#[test]` regression and the smallest idiomatic repair—folding co-dependent repairs or stacking them in `depends_on` order when an earlier fix unmasks a deeper divergence—keeping reference models and broad generators on the local discovery branch.
- **Internal or team-owned codebases:** finish a lone isolated bug with a clean local fix; when the workspace sweep shows multiple failures or call sites sharing one underlying representation gap, apply [`root-and-branch`](../root-and-branch/SKILL.md) (culling duplicate wrappers so `ΔConcepts <= 0` and tightening types so `|Type| == |ValidStates|`).
- **Unsettled contracts, tradeoffs, and maintainer channels:** when two defensible interpretations fit the docs, or changing behavior alters public semantics, memory layout, or asymptotic complexity tradeoffs that maintainers should weigh directly, provide a reproduction-only unit test (paired with a nearby passing baseline when one exists) and a concise option summary (using [`write-reports`](../write-reports/SKILL.md) if loaded); when `CONTRIBUTING.md`, `SECURITY.md`, or user instructions designate a non-public maintainer path, write the standalone unit test and notes to an output directory **outside the git worktree** so subsequent `git add .` commands never stage them.

Whenever the contract establishes an expected result, apply the test-only diff to a disposable checkout of the **delivery parent SHA** and run the exact decisive `gate_command` (including `Miri`/`ASan` or feature flags whenever an instrumented runtime served as the regression gate) to confirm the named `#[test]` ran and failed with the expected diagnostic, then run `gate_command` (plus `--release` parity) on the **delivery branch tip SHA** (`confirming post-fix pass`), record both SHAs alongside `worker_base_sha`, rerun `law_checked` (plus any initial `model_law` as a regression guard) over the recorded operations on the discovery branch, commit validated fixes (`updating worker_base_sha`) to unmask deeper layers, and let the next iteration explore what opens up behind them.

Use [`references/methods.md`](references/methods.md) when grounding or extending these specification, generator, and fix-verification methods.
