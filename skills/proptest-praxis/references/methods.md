# Specification and property-testing methods

These sources establish the underlying specification, generator, and verification concepts applied in [`SKILL.md`](../SKILL.md); select and combine the patterns that fit the target module.

| Method | Contribution to property-based verification | Source |
| --- | --- | --- |
| Property-based testing and shrinking | Express specifications as universally quantified executable laws over generated algebraic values with automatic counterexample reduction. | [Claessen and Hughes, QuickCheck: A Lightweight Tool for Random Testing of Haskell Programs](https://www.cs.tufts.edu/~nr/cs257/archive/john-hughes/quick.pdf) |
| Five-rung property taxonomy | Choose among model-based homomorphisms, invariants, roundtrips/idempotence, commuting paths ("two ways to do it"), and structural postconditions so specifications stay concise without retreating to smoke checks. | [Hughes, How to Specify It! A Guide to Writing Properties of Pure Functions](https://research.chalmers.se/publication/517894/file/517894_Fulltext.pdf) |
| Data refinement and refinement mappings | Verify concrete state machines `C` against simple abstract models `A` via commuting abstraction functions `alpha(step_C(c, op)) = step_A(alpha(c), op)` and representation invariants `RepInv(c)`. | [Hoare, Proof of Correctness of Data Representations](https://link.springer.com/article/10.1007/BF00289507); [Lamport, The Existence of Refinement Mappings](https://lamport.azurewebsites.net/pubs/refinement.pdf) |
| Myhill–Nerode state distinguishability | Construct distinct operation histories `h1, h2` reaching equal abstract states `alpha(c1) = alpha(c2)` and search for a suffix `w` that exposes hidden concrete state differences (caches, tombstones, lazy fields). | [Nerode, Linear Automaton Transformations](https://www.ams.org/journals/proc/1958-009-04/S0002-9939-1958-0135681-9/) |
| Small-scope hypothesis | Concentrate search on tiny domains (`0..4` keys, `"a"`/`"b"` crossed with grammar delimiters) where birthday-paradox and boundary collision density are highest. | [Jackson, Software Abstractions: Logic, Language, and Analysis](https://softwareabstractions.org/) |
| Swarm testing | Mix per-trace `3–5` operation subsets (preventing `Clear` or eager `Get` from suppressing capacity and cold-snapshot states) with full-vocabulary traces (`AllOps`) so multi-operation chains remain reachable. | [Groce et al., Swarm Testing](https://agroce.github.io/issta12.pdf) |
| Differential testing | Use a second implementation already in the repository (scalar fallback vs. SIMD, cold batch vs. incremental, owned vs. zero-copy view) as a zero-reimplementation oracle. | [McKeeman, Differential Testing for Software](https://www.hpl.hp.com/hpjournal/dtj/vol10num1/vol10num1art9.pdf) |
| Result checking and planted solutions | Verify non-unique or expensive outputs in linear time (certificates, topological order + multiset conservation) or plant a valid solution to prove instance feasibility and bound the objective under the API's ordering (comparing exact answers only when uniqueness holds). | [Blum and Kannan, Designing Programs That Check Their Work](https://dl.acm.org/doi/10.1145/200836.200880) |
| Metamorphic testing and Equivalence Modulo Inputs (`EMI`) | Test compilers, planners, and solvers without a ground-truth model by applying semantics-preserving or predictable input transforms (`e ~ e' => eval(e) = eval(e')`). | [Chen et al., Metamorphic Testing: A Review of Challenges and Opportunities](https://dl.acm.org/doi/10.1145/3143561); [Le, Afshari, and Su, Compiler Validation via Equivalence Modulo Inputs](https://dl.acm.org/doi/10.1145/2594291.2594334) |
| Rely–Guarantee and Separation Logic frames | Decompose cross-module pipelines via explicit `produce -> consume` obligations (`produce(x)` satisfies `consume`'s precondition) and spatial frame laws (`modifies(work) * UNCHANGED(outside)`). | [Jones, Tentative Steps Toward a Development Method for Interfering Programs](https://dl.acm.org/doi/10.1145/69575.69577); [Reynolds, Separation Logic: A Logic for Shared Mutable Data Structures](https://www.cs.cmu.edu/~jcr/seplogic.pdf) |
| Fix-neighborhood regression analysis | Reactive point-fixes written under time pressure against a single failing input (hotfixes, release-blocker patches, security fixes, crash band-aids) frequently introduce adjacent correctness regressions or update only one side of a coupled invariant. | [Yin et al., How Do Fixes Become Bugs?](https://dl.acm.org/doi/10.1145/2025113.2025121) |
| Delta debugging (`ddmin`) | Isolate minimal failure-inducing steps and input clauses systematically once a witness is found. | [Zeller and Hildebrandt, Simplifying and Isolating Failure-Inducing Input](https://dl.acm.org/doi/10.1109/32.988498) |
