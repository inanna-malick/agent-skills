# Rust property-testing harness (`proptest`)

Apply these Rust-specific patterns alongside the specification, generator, and effect-reification principles in [`SKILL.md`](../SKILL.md).

**Fast leaf loops (`0.5–3s`).** Place discovery properties inside the narrowest leaf crate (`cargo test -p <leaf> --lib <law_name>`) or a minimal pocket test target rather than linking workspace-wide integration binaries on every edit (verifying that Cargo actually discovers and executes the target test file rather than leaving a nested `tests/subdir/*.rs` module unlinked). Add `proptest = "1"` under `[dev-dependencies]` in the disposable workspace (removing temporary dev-dependency edits before staging final unit-test deliverables unless the crate already depends on `proptest`), and keep `CARGO_TARGET_DIR` isolated per snapshot when running parallel worker or mutation-challenger trees of the same crate (sharing `CARGO_HOME` rather than a live `target/` directory so concurrent builds never execute stale or mutated binaries). Scale iteration budgets cleanly via environment variables: iterate generator compilation at `PROPTEST_CASES=64`, then widen to `PROPTEST_CASES=1000..5000` once the model commutes on initial runs. Redirect verbose cargo/runner output to a log file (`> /tmp/proptest.log 2>&1`) and inspect compact `file:line` frames and minimal failing inputs.

**Index-driven generators and shrinking.** Define an explicit `#[derive(Debug, Clone)] enum Op` over uninterpreted finite sorts (`Key(0..4)`, `Atom(0..4)`) rather than chaining `prop_flat_map` or filtering with `prop_assume!`. Select keys, existing handles, and active entries via `proptest::sample::Index` (`idx.index(live.len())`) so shrinking preserves valid target selection as earlier operations are deleted. When combining `Op` variants under Groce swarm testing, draw a per-trace variant subset mask first (`prop::bits::u8::sampled(3..6, 0..8)`) alongside full-vocabulary traces, and order struct/tuple fields so outer operation vectors shrink before inner values.

**Pure `FsMap` and subprocess state.** `proptest!` executes hundreds of trials and shrink steps inside one process. Reify filesystem state per trial with `tempfile::TempDir::new()` *inside* the `proptest!` closure—never in a shared `OnceLock` or outer test body—materializing an explicit `BTreeMap<PathBuf, Entry>` under `root/d0/d1/work` alongside sibling entries (`root/a`, `root/d0/a`) and asserting `snapshot_tree(temp.path()) == model_tree`. When code under test reads `$HOME`, `$TMPDIR`, or process `cwd`, invoke a child `std::process::Command` with `.env_clear()`, explicit `.env(...)` bindings, and `.current_dir(&work)`.

**Standard CI build matrix (`--release`, `Miri`, concurrency schedules).**
- **Release parity:** Always run regression tests and candidate patches under `cargo test --release`, where wrapping `Z_2^w` arithmetic, `debug_assert!` elision, and LLVM optimization passes can differ from debug builds.
- **`unsafe` CI verification (`Miri`):** On modules using `unsafe`, `Pin`, raw pointers, or custom collections, include standard Rust `Miri` CI checks (`PROPTEST_DISABLE_FAILURE_PERSISTENCE=1 PROPTEST_CASES=16 cargo +nightly miri test -p <leaf> <law_name> > /tmp/miri.log 2>&1`), inspecting compact `file:line` frames so `unsafe` invariants and proposed fixes pass `cargo miri` cleanly.
- **Concurrency schedules:** On lock-free queues, caches, or atomics where interleavings determine `alpha(c)`, pair sequential `proptest` suites with `loom` or `shuttle` schedule exploration over `2–3` threads and `0..3` keys.

**Clean `#[test]` extraction.** Once `proptest` shrinks to a minimal `Op` sequence (`ddmin` fixed point), write a plain, dependency-free `#[test]` function at the established contract boundary calling the concrete API directly with literal values (`sut`, `expected`) and `assert_eq!`, leaving temporary `proptest-regressions/` files and discovery helpers out of the final patch.
