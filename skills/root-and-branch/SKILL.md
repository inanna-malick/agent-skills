# Root and branch: eliminating whole bug classes in owned codebases

Minimal five-line patches optimize for stranger-maintained repositories where reviewer attention is scarce and internal types are someone else's territory. In a codebase your own team maintains—where compilers and property suites verify wide structural refactors at `O(1)` marginal cost—patching one symptom at a time accretes boolean flags, compensating adapters, and duplicate wrappers. Treat a defect in owned code as **placer gold washing down from an upslope vein**: trace the vein to its source, pan the workspace for the idiom that produced it, and pull the whole bug class out by the roots.

Select and combine the lenses below whenever fixing defects, reviewing changes, or refactoring an owned codebase.

**Upslope dataflow; representation splits; syntactic-habit panning.** Step above the failing helper to trace `produce -> representation -> consume` across module boundaries, watching for **internal `stringify -> reparse` roundtrips** (formatting a typed identifier, path, query, or error enum into a raw `String` only to `.contains(...)`, `strip_prefix(...)`, or re-parse it upstairs) and split state where two structs or caches track one fact independently. Because fragile idioms repeat, grep the verb rather than the noun across sibling files: silent fallback masking (`unwrap_or_default()`, `.ok()`, `let _ =`, bare `except:` / `catch`), stringly-typed dispatch (`.to_lowercase()`, `.contains(`, `strip_prefix(`, regex splitting), exhaustiveness wildcards (`_ =>` / `default:` muting compiler checks like `rustc E0063`), `Option<bool>` or multi-`bool` state bags, stored shadow verdict booleans (`is_valid: bool`), and duplicate pocket wrappers induced by inverted package/crate dependency arrows.

**Proportional scope; accidental vs. essential complexity; three-adapter rule.** Let the workspace sweep govern repair depth: finish a genuinely isolated local slip with a small fix and unit test rather than forcing a refactor. When multiple failures or call sites share one representation gap, check **10,000-foot product reality** first (Brooks's essential vs. accidental complexity): whenever a mechanism demands its **third compensating adapter or special-case flag**, pause and ask the human owner one concise two-line question so obsolete prototype scaffolding gets deleted rather than memorialized in types.

**Concept culling (`ΔConcepts <= 0`); cardinality alignment (`|Type| == |ValidStates|`); standard abstractions.** Prefer structural fixes that leave the codebase with *fewer* distinct concepts than before: delete dead fallback strata, merge parallel `foo` / `foo_v2` paths, and invert tangled package arrows so duplicate helpers evaporate. Tighten carrier types so invalid or out-of-envelope states become unrepresentable (**parse, don't validate**): construct validated newtypes (`ValidatedQuery`, `NormalizedPath`, `NonZeroUsize`) once at the boundary (`#[serde(try_from)]`), replace boolean bags with closed sum types, compute summary verdicts via methods rather than stored `bool` fields, omit `_ =>` wildcards on internal enums so the compiler routes future variants automatically, and swap 85%-complete hand-rolled scanners or formatters for mature crates and visitor traits (`sqlparser::ast::Visitor`, `url`, `serde`, `tree-sitter`).

**Equivalence-class verification; public-boundary regression tests; release parity.** Cover both the original site and sibling call sites uncovered by the sweep with a deterministic unit or property test at the module boundary, confirming pre-fix failure and post-fix pass across debug and `--release` builds so the bug class is closed cleanly.
