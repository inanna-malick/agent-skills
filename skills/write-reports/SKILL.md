# Write Reports

A great technical report has the clarity of a four-line mathematical counterexample: a reader who has never seen your investigation transcript, generator, or reference model can run or trace the minimal case in seconds, see the exact invariant or contract that failed, and make a concrete engineering decision.

Select and combine the lenses below as the audience, venue, and finding require.

**Decision space; audience design; inverted pyramid.** Identify who reads the artifact and what choice it supports: merging an obvious patch, weighing a semantic or performance tradeoff, answering a specification question, or triaging a backlog item. Lead with the concrete function, minimal input, observed result, and expected behavior. Use flat, plain-prose report and PR titles stating the component and broken invariant (`SelectionMap: equal values produce different hashes`, `tsdb: chunk reload shifts subsequent timestamp`) paired with neutral test identifiers (`selection_map_equal_values_hash_differently`), and translate internal harness terms (`alpha`, `RepInv`, local discovery branches) into the project's native domain vocabulary.

**Counterexample compression; contrastive baseline; exact provenance.** Strip away every incidental operation and parameter until only the minimal deterministic witness against the pinned base commit remains (`10, 11` then reopen and append `13` reading back `10, 11, 12`; `abcd` in Replace mode recovering `Xabcd` instead of `Xbcd`). Pair the failing case with its nearest passing baseline (unchunked vs. chunked on the same bytes; fresh vs. warmed cache on the same keys) so the delta isolates the broken invariant at a glance. Record the exact base commit SHA (plus any prerequisite fix commit when a deeper divergence was masked by an earlier bug), build profile (`debug` vs. `--release`), feature flags, runtime checks (`Miri`, `ASan`, `UBSan`), and runnable command.

**Domain provenance; diagnostic honesty; witness-led precision.** Maintainers trust reports that claim exactly what their witness establishes. Ground every report in verified diagnostic facts: the named API whose contract the test exercises, input domain, documented caller obligations, minimal executable test, observed vs. expected behavior, verified build/runtime flags, and proposed repair (when the contract determines one). Distinguish a documented caller precondition from an incidental habit of current outer callers: if an inspected caller passes a fresh copy, normalizes upstream, or avoids the sequence, cite it plainly; otherwise mark uninspected caller behavior `unverified` and let the minimal executable counterexample carry the weight of the claim.

**Root-cause quotienting; equivalence classes; atomic scope.** Group findings by underlying representation invariant and repair boundary rather than by surface symptom or call site. Collapse multiple failing traces resolved by restoring one invariant into a single report; keep independent mechanisms separate so each change can be reviewed, merged, or reverted cleanly.

**Epistemic calibration; specification vs. ambiguity; cross-model verification.** Distinguish clear contract violations from undocumented corner cases, asymptotic complexity cliffs, or intentional simplifications. Before surfacing a report, review the claim skeptically—across a second model family when available—against documentation, explicit caller preconditions, existing tests, and `--release` behavior, iterating until the reproduction is self-contained and minimal in lines of code. Frame genuine ambiguity as a concise specification question, and update or withdraw claims plainly when maintainer context changes the picture.

**Repair ownership; surgical patches, root-type fixes, and reproduction-only.** Match the proposed action to repository ownership and maintainer latitude. For external repositories, supply the smallest complete, idiomatic fix when the contract is clear, noting briefly why the change restores the invariant across sibling paths without regressing fast paths or valid callers. For team-owned repositories, note when sibling failures warrant tightening a shared type (`|Type| == |ValidStates|`) rather than adding point guards. Supply a reproduction-only unit test and a concise comparison of candidate contracts when changing behavior affects public semantics, memory layout, asymptotic complexity, or module boundaries that maintainers should weigh deliberately.

**Channel fit; routing discipline; artifact hygiene.** Match format, detail, and visibility to the project's `CONTRIBUTING.md`, `SECURITY.md`, or team workflow. When project norms designate a private maintainer path for a finding, keep the unit reproduction and notes on that path rather than public branches, issues, or unrelated pull requests until cleared.
